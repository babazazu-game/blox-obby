# base-three

Заготовка новой игры под Яндекс.Игры на **Three.js + TypeScript + Vite**.

Тот же каркас площадки, что и у Phaser-игр (`yg-core`), но рендер и цикл
кадров свои. Брать эту заготовку стоит тогда, когда игре действительно нужен
настоящий 3D: подвижная камера, свет, меняющийся в реальном времени,
физика, вращение предметов.

**Когда НЕ брать.** Если сцена статична — камера не двигается, свет не
меняется, предметы только перемещаются, — 3D тут лишний. Такой кадр
рендерится один раз в Blender и кладётся спрайтом, а игра идёт на Phaser
и не считает каждый кадр то, что можно запечь заранее. Ровно так сделан
«МикроБум»: колбы и фишки выглядят объёмными, но это картинки.

## С чего начать

```bash
npm install
npm run dev
```

Дальше по порядку:

1. `index.html` — название игры, цвета и фигура на экране загрузки.
2. `src/locale/{ru,en}.ts` — строки. Порядок ключей в обоих файлах одинаков.
3. `src/game.ts` — сцена. Сейчас там пол и вращающийся куб; заменить своим,
   оставив четыре вещи, помеченные в комментарии сверху.

## Что уже сделано

| Файл | Что закрывает |
|---|---|
| `src/main.ts` | порядок «SDK → рендерер → сцена → `ready()`», HiDPI через `setPixelRatio` с потолком, слежение за размером контейнера |
| `src/game.ts` | ортокамера от фактического аспекта, цикл через `setAnimationLoop`, пауза по уходу со вкладки |
| `src/ads.ts` | правила показа рекламы: где можно звать и что делать, если не показали |
| `tools/make_zip.py` | архив с ПРЯМЫМИ слешами — иначе площадка отдаёт 404 на всё вложенное |

## Чего здесь пока нет

Интерфейса. В Phaser-заготовке есть готовые кнопки и окна, потому что там всё
рисуется на холсте; в Three.js так не делают — интерфейс кладут DOM-слоем
поверх канваса. Когда дойдёт до первой 3D-игры, слой появится здесь же,
и вот тогда `yg-core/viewport` (`fontPx`, `tapSize`) пригодится и ему:
предел кегля 13 px и зона нажатия 44 px — требования площадки, а не движка.
